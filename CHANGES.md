# Changes

This file tracks notable new functionality added to pdp11gui. See `CLAUDE.md` for the rule that keeps it up to date.

## 2026-07-24

- **SimH direct picks free telnet ports per launch.** The generated `.ini` used a hardcoded 4000/4001 pair. SimH does not set `SO_REUSEADDR`, so after pdp11gui exits, the port that carried the remote-console connection stays unbindable for the length of its `TIME_WAIT`: restarting within about a minute left SimH running with its remote console disabled (`%SIM-ERROR: Can't open network port: 4000`), i.e. an emulator the GUI could not drive, reported only on stdout. `TSerialIoHub.FindFreeSimhPorts` now probes upwards from 4000/4001 in steps of two for a bindable pair (without `SO_REUSEADDR`, so a `TIME_WAIT` port correctly counts as busy, matching what SimH itself can do) and the chosen pair is written into the `.ini` and used for both telnet connections. Also lets several SimH-direct instances run at once. See `SerialIoHubU.pas`.
- **Startup connection failures say what went wrong.** `StartupTimerTimer` caught any exception from the initial connect and silently showed the settings dialog, so an unreachable machine, a missing `pdp11` on `PATH` or the port problem above all presented as an unexplained settings dialog. The exception message is now logged and shown in an error dialog first.
- **Settings are stored again on Linux.** No setting of any kind survived a restart: window positions, serial parameters, the selected PDP-11 configuration and the SimH `.ini` path were all silently discarded, so every run started from scratch. On non-Windows platforms `TRegistry` is backed by an XML file (`~/.config/pdp11GUI/reg.xml`) whose `AutoFlush` is off, so writes only ever reached an in-memory tree; the tree was flushed on `CloseKey`/destruction, but `RegistryU.pas` had no `finalization` and never freed the global `TheRegistry`, and `TJH_Registry`'s own periodic save was a no-op because it required a `Filename` that is never assigned (and called `SaveToFile`, which raises "not supported on this platform"). `TJH_Registry` now has a `Flush` method that is called both by the existing 5-second save timer and at unit finalization. See `common/JH_Utilities.pas` and `Pdp11gui/RegistryU.pas`.
- **No more spurious console error on startup.** With nothing stored, the configuration combobox fell back to index 0 - "Physical PDP-11 with M9301 over serial port" - and `StartupTimerTimer` connected to it unasked, so every start put up a "Could not wake up ..." console error for hardware the user never selected. The settings form now distinguishes a genuinely stored selection from that fallback (`TFormSettings.hasStoredSelection`); when there is none, the settings dialog is shown instead of a connection being attempted, and `TFormMain.ApplySettings` does nothing while no configuration has been chosen.
- **Console error messages name the right console.** `TConsolePDP11M9301` descends from `TConsolePDP11M9312` and inherited its `Resync` with a hardcoded "PDP-11 M9312 console emulator" in the failure message, so an M9301 failure was reported as an M9312 one. The message is now built from the virtual `getName`, and `TConsolePDP11M9301` overrides it (it previously inherited the M9312 name there too).
- **Uniform behaviour of all file open/save dialogs.** Every file dialog in the program (machine description, MACRO-11 source and listing, memory loader/dumper, disk image and meta info, SimH `.ini` script, micro code listing, blinkenlight program, SimH script export) now goes through `ExecuteFileDialog()` in the new unit `FileDialogsU.pas`: the first dialog of a program run starts in the user's home directory, every later one starts in the directory used last, and hidden files are not shown. Previously each dialog picked its own start directory (application data directory, the directory of some previously configured file, or the current working directory). Not showing hidden files needs one extra step on Linux/GNOME: Qt hands file dialogs over to the desktop's GTK3 file chooser, which ignores `InitialDir` and follows the desktop-wide "show hidden files" setting, so `InitFileDialogs()` (called from `pdp11GUI.dpr` before `Application.Initialize`) sets Qt's `AA_DontUseNativeDialogs` attribute and Qt's own file dialog is used instead.
- **"SimH direct" connection.** A new console connection type, selectable in the settings dialog as "SimH direct (pdp11gui launches SimH)". Instead of requiring the user to start `open-simh` by hand and configure its remote console, pdp11gui now launches the `pdp11` executable itself (found on `PATH`) using a generated copy of the chosen `.ini` file, and connects to it over two telnet links: one to SimH's "remote console" (the `sim>` command interface used for examine/deposit/run/reset) and one to the emulated PDP-11's own serial console. See `ConsolePDP11SimHU.pas` and `SerialIoHubU.Physical_InitForSimhProcess`.
- **CPU run-state tracking for the SimH console.** `ConsolePDP11SimHU.pas` now tracks whether the emulated CPU is actually running or halted (`TSimhCpuState`), derived only from confirmed events on the remote console (a `"Simulator Running..."` acknowledgment, an explicit halt message, or any `sim>` prompt reappearing) rather than assumed from whichever button was clicked. This fixed a cluster of related bugs: `Halt` no longer sends `^E` into an already-idle session (which SimH would silently ignore, leaving the displayed PC as `?`); a program that self-halts immediately after `Run` (eg. no code loaded, PC pointing at zeroed/HALT-opcode memory) is now detected and the UI updated automatically, without waiting for a `Halt` click that would otherwise send nothing. Detection is entirely event-driven with no timeout-based guessing - an earlier version of this fix that used a bounded wait after `Run` to decide "did it self-halt?" turned out to be a real hazard: guessing wrong on a genuinely-running program caused an unsolicited command to interrupt it, which SimH's remote console has no ordinary way to recover from (only `^E` resumes from that state, not a plain `RUN` retry).
- **"SimH Remote Console Log" window.** New optional MDI window (Connection menu) showing a live, timestamped transcript of every command sent to and phrase recognized from SimH's remote console - the protocol-level view used to diagnose the run-state issues above, kept as a permanent debugging aid instead of one-off log statements. See `FormSimhRemoteLogU.pas`.
